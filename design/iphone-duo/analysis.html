What this canvas decides (for review, Phase 5)

One rule from the container shape. Wider than tall → board pane + column (HStack). Taller than wide → stacked (VStack). An active division moves the split onto the fold (FB: left page / right page; FT: top half / bottom half). AnyLayout switches between them so GameViewModel, selection and unsaved moves survive (§6.15). Board size is computed from the container, never the device.

Every control is a system toolbar item. Top: Back, Flip Board, Engine Lines (toggle), and the overflow menu. Bottom (.bottomBar): Previous / Next Move. The system puts them in the side bar on O, SV, IL and FB (top items at the top, bottom items at the bottom), and in the navigation bar and bottom toolbar on IP, FT and iPad. This replaces today's custom capsule (.safeAreaBar), so nothing custom has to track toolbarVerticalEdge, and the move list gains the capsule's 64 pt.

Overflow. The game ⋯ menu becomes ToolbarOverflowMenu (F16): Save / Edit Details / Add Comment · Show/Hide Evaluation · Copy PGN / Export PGN… · Delete Game. Ellipsis now means overflow only.

Alternatives are a wrapping row of 44 pt chips in the column, under the board on compact (F8, F9). Promotion is a row of four 56 pt buttons in the column, so the board stays visible (F12). Confirmation dialogs are attached to the control that asks: the move row or the overflow item (F15). Save as Game uses a fitted sheet (F17, F29). Offline banner shows in Puzzle analysis (F14).
